Four repositories, one contract

On each platform the work ships as two packages — a small bridge (API + loader, its own semver) and a runtime (engine only, versioned exactly like Node.js). They meet only at process runtime.

One process. One engine. Two packages.

The bridge is just a loader and a JSON-speaking host. It never links the engine; it finds libnode.so at runtime with dlopen and enters it through node::Start(int, char**). The engine itself is an ordinary shared object — ET_DYN, no PT_INTERP.

The NAPI addon leaves its napi_* symbols undefined on purpose (-z undefs); they resolve against the already-loaded engine (RTLD_GLOBAL), so Node's own N-API implementation is always used. Swap Node versions without recompiling the bridge.

  • libnode_bridge.soloader — links only log/dl; dlopen + dlsym
  • libnode_host_client.soNAPI addon, loaded via process.dlopen
  • libnode.soNode.js + V8, from the runtime package
  • bootstrap.js · host.jsJS payload, materialized from app assets
01

Contract, not linkage

The only required symbols are node::Start and the stable N-API surface. The bridge does not know or care which Node minor version provides them.

02

Two packages per platform

A ~half-MB bridge on its own semver, and a ~41 MB engine whose version is the Node version. Ship bridge fixes without touching the engine, and vice-versa.

03

Pinned, reproduced, verified

Every engine is CI-cross-compiled from the official Node tarball. SHA-256 is locked in runtime.lock.json; 7 ELF gates check ET_DYN, PT_INTERP=0, ABI and the exported entry point.

04

Failures stay visible

Idle → Starting → Running → Exited/Failed is an observable state machine. Hard platform limits are reported to the caller — never papered over.

Honest constraints — reported, never silently degraded

  • node::Start runs once per process; a crash is terminal. Use a dedicated :node process for restartability.
  • HarmonyOS targets 2in1 / tablet only (no phone); Android needs minSdk 24. arm64-v8a is the only ABI.
  • App assets are not a filesystem path; the JS payload is materialized into the app sandbox before start — the library handles it.
  • JIT is verified on real hardware: JIT and WebAssembly confirmed working on Android 15 and HarmonyOS 2in1 devices.
